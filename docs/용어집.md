# secrethound 용어집

이 프로젝트(README, 기획서, 코드)에 나오는 용어를 처음 보는 사람 기준으로 정리했습니다.

## 1. 프로젝트가 다루는 대상

| 용어 | 뜻 |
|---|---|
| **시크릿 (secret)** | API 키, 비밀번호, 토큰처럼 외부에 노출되면 안 되는 값을 통틀어 부르는 말 |
| **API 키 / 토큰 (token)** | 어떤 서비스(AWS, GitHub, Slack 등)에 "나는 인증된 사용자다"라고 증명할 때 쓰는 문자열. 비밀번호와 비슷한 역할 |
| **크리덴셜 (credential)** | 인증에 쓰이는 정보 전반(키, 토큰, 개인키, DB 접속 정보 등)을 묶어 부르는 말 |
| **하드코딩 (hardcoding)** | 설정 파일이나 환경변수 대신 소스 코드에 값을 직접 박아 넣는 것. 시크릿을 하드코딩하면 코드와 함께 유출됨 |
| **.env 파일** | 비밀 값을 코드와 분리해서 담아두는 환경변수 파일. 보통 git에는 커밋하지 않음 |
| **PEM 개인키** | 서버·SSH 등에서 쓰는 암호화 키 파일 형식. 유출되면 해당 서버에 접근 가능해짐 |
| **JWT (JSON Web Token)** | 로그인 상태 등을 담아 서버-클라이언트가 주고받는 토큰 형식 |
| **DB 접속 문자열 (connection string)** | `postgres://user:password@host/db` 처럼 데이터베이스 접속 정보를 한 줄에 담은 문자열 |
| **PII (Personally Identifiable Information)** | 주민등록번호, 카드번호 등 개인을 식별할 수 있는 정보. 이 프로젝트가 찾는 "시크릿"과는 다른 카테고리로 취급함 |
| **DLP (Data Loss Prevention)** | 개인정보·기밀정보 유출을 막는 보안 분야 전체를 가리키는 용어. PII 탐지는 DLP 영역이라 이 프로젝트 범위 밖으로 분리해둠 |

## 2. Git 관련 용어

| 용어 | 뜻 |
|---|---|
| **레포 (repo, repository)** | git으로 관리되는 프로젝트 폴더 전체 |
| **커밋 (commit)** | 코드 변경사항을 하나의 기록 단위로 저장한 것. 각 커밋은 고유한 해시(예: `be880d7`)를 가짐 |
| **커밋 히스토리 (commit history)** | 지금까지 쌓인 커밋들의 전체 기록. 파일에서 값을 지워도 히스토리에는 그대로 남아있음 |
| **워킹트리 (working tree)** | 지금 눈에 보이는, 현재 상태의 파일들. "히스토리"와 대비되는 개념 — 워킹트리는 깨끗해도 히스토리엔 옛날 시크릿이 남아있을 수 있음 |
| **`git log -p`** | 커밋들의 변경 내용(diff)까지 함께 출력하는 git 명령어. 이 프로젝트는 이 출력을 파싱해서 과거 커밋까지 스캔함 |
| **diff** | 두 시점 사이에 무엇이 추가/삭제됐는지 보여주는 변경 내역 |
| **hunk** | diff 안에서 "몇 번째 줄부터 몇 줄이 바뀌었다"를 나타내는 한 블록. hunk 헤더를 읽으면 그 줄이 원래 파일의 몇 번째 줄이었는지 알 수 있음 |
| **얕은 클론 (shallow clone)** | 전체 히스토리 대신 최근 커밋 몇 개만 내려받는 것. `fetch-depth: 0`을 안 주면 GitHub Actions가 이렇게 받아서, 히스토리 스캔이 최근 커밋만 보게 됨 |

## 3. 이 프로젝트의 탐지 방식 관련 용어

| 용어 | 뜻 |
|---|---|
| **정규식 (regex, regular expression)** | 문자열 패턴을 표현하는 규칙. `AKIA[A-Z0-9]{16}` 처럼 "이런 모양의 문자열을 찾아라"를 정의함 |
| **키워드 프리필터 (keyword prefilter)** | 정규식을 돌리기 전에 특정 단어(예: `svc_`)가 있는 줄만 먼저 골라내는 단계. 모든 줄에 정규식을 다 돌리면 느리므로 성능 최적화용 |
| **엔트로피 (entropy, Shannon entropy)** | 문자열이 얼마나 "무작위"한지를 수치로 나타낸 것. 랜덤하게 생성된 키는 엔트로피가 높고, `aaaa1111` 같은 반복 문자열은 낮음. 정규식으로 못 잡는 형식 없는 랜덤 문자열을 걸러낼 때 보조로 씀 |
| **캡처 그룹 (capture group)** | 정규식에서 괄호 `()`로 묶어 "이 부분만 따로 꺼내겠다"고 지정하는 부분. `secret_group`은 매치된 결과 중 실제 시크릿 값이 담긴 그룹 번호 |
| **RE2 엔진** | Go 언어의 정규식 엔진 이름. lookahead(`(?=)`), lookbehind(`(?<=)`), 백레퍼런스(`\1`) 같은 일부 고급 기능을 지원하지 않는 대신 속도가 안정적임 |
| **오탐 (false positive, FP)** | 시크릿이 아닌데 시크릿이라고 잘못 판단한 것. 예: 문서에 적힌 예시 키 `AKIAXXXXXXXXXXXXXXXX` |
| **미탐 (false negative, FN)** | 진짜 시크릿인데 놓친 것. 이 프로젝트는 "미탐이 오탐보다 손해가 크다"는 원칙으로 설계됨 |
| **신뢰도 점수 (confidence score)** | 탐지된 값이 "진짜 시크릿일 가능성"을 0~100으로 매긴 점수. 플레이스홀더 문구 포함, 반복 문자 등을 보고 감점함 |
| **임계값 (threshold)** | 이 값 밑으로 떨어지면 결과에서 제외하는 기준선. `min_confidence`(기본 50)가 이 프로젝트의 임계값 |
| **화이트리스트 / allowlist** | "이건 예외로 봐줘"라고 미리 등록해둔 규칙·경로·값 목록 |
| **penalty (감점 규칙)** | 신뢰도 점수를 깎는 조건. 예: 경로에 `sandbox/`가 있으면 -50점 |
| **occurrence (출현 횟수)** | 같은 시크릿 값이 여러 곳에서 몇 번 발견됐는지 |

## 4. 아키텍처(내부 구조) 용어

기획서/README에 나오는 파이프라인 이름들입니다. 코드는 `internal/` 폴더 아래 같은 이름의 패키지로 대응됩니다.

| 컴포넌트 | 하는 일 |
|---|---|
| **Repo Collector** (`internal/collector`) | 현재 파일들 + git 히스토리를 순회하며 스캔할 텍스트를 모아옴 |
| **Detection Engine** (`internal/detector`) | 정규식 매칭 + 엔트로피 검증으로 시크릿 후보를 찾아냄 |
| **FP Filter** (`internal/filter`) | 찾은 후보들 중 오탐(false positive)을 걸러내고 신뢰도 점수를 매김 |
| **Reporter** (`internal/reporter`) | 최종 결과를 심각도순으로 정리해 텍스트/JSON으로 출력 |
| **Validator** (`internal/validator`) | `--validate` 옵션을 켰을 때 발급처 API에 실제로 키가 살아있는지 물어보는 부분 |

## 5. 키 유효성 검증(`--validate`) 관련 용어

| 용어 | 뜻 |
|---|---|
| **유효 (valid)** | 발급처가 "이 키로 인증 성공"이라고 확인해준 상태. 지금 실제로 위험한 키 |
| **폐기됨 (revoked)** | 발급처가 인증을 거부한 상태. 키가 이미 무효화됐다는 뜻이지, 애초에 탐지가 잘못됐다는 뜻은 아님 |
| **검증불가 (unknown)** | 네트워크 문제·레이트리밋·미지원 등으로 판단을 내릴 수 없는 상태 |
| **STS (Security Token Service)** | AWS의 신원 확인용 서비스. `sts:GetCallerIdentity`는 아무 권한 없이도 "이 키가 살아있는지"만 확인할 수 있는 API |
| **IAM (Identity and Access Management)** | AWS에서 "누가 무엇을 할 수 있는지" 권한을 관리하는 시스템 |
| **SigV4 (Signature Version 4)** | AWS API 요청에 서명(署名)을 붙이는 방식. AWS는 토큰 하나만 보내는 게 아니라 Access Key + Secret Key로 요청 자체를 암호학적으로 서명해야 함 |
| **HMAC / SHA-256** | SigV4 서명을 만들 때 쓰는 암호학 해시 알고리즘 |
| **레이트리밋 (rate limit) / 429** | "요청을 너무 많이 보냈다"는 뜻의 HTTP 상태코드. `Retry-After` 헤더는 "몇 초 후에 다시 시도하라"는 안내 |
| **Webhook** | 특정 이벤트가 생기면 미리 정해둔 URL로 자동으로 메시지를 보내는 방식(예: Slack Incoming Webhook) |
| **selfcheck** | 진짜 키 없이 가짜 형식의 키를 보내서, 발급처의 거부 응답이 예상한 형태(예: GitHub의 401 + "Bad credentials")와 여전히 일치하는지 정기적으로 점검하는 기능. 발급처가 API를 바꾸면 여기서 먼저 발견됨 |

## 6. CI/CD, 배포 관련 용어

| 용어 | 뜻 |
|---|---|
| **CI (Continuous Integration)** | 코드를 올릴 때마다 자동으로 빌드/테스트/검사를 돌리는 시스템 |
| **GitHub Actions** | GitHub에서 제공하는 CI 자동화 기능. `.github/workflows/*.yml`로 정의함 |
| **워크플로 (workflow)** | GitHub Actions에서 "이런 이벤트가 생기면 이런 작업들을 실행해라"를 정의한 파일 |
| **종료 코드 (exit code)** | 프로그램이 끝날 때 반환하는 숫자. 0=정상, 1=시크릿 탐지됨, 2=실행 실패처럼 의미를 나눠서 CI가 구분할 수 있게 함 |
| **PR (Pull Request)** | 코드 변경을 메인 브랜치에 합쳐달라고 요청하는 것. 이 프로젝트는 PR에 시크릿이 들어오면 CI를 실패시킴 |
| **checkout** | GitHub Actions에서 레포 코드를 실행 환경으로 내려받는 단계 |

## 7. 정확도 측정(eval) 관련 용어

| 용어 | 뜻 |
|---|---|
| **Precision (정밀도)** | "시크릿이라고 보고한 것 중 실제로 맞은 비율". 오탐이 적을수록 높음 |
| **Recall (재현율)** | "실제 시크릿 중 놓치지 않고 찾아낸 비율". 미탐이 적을수록 높음 |
| **F1 스코어** | Precision과 Recall을 하나로 합친 점수. 둘 다 높아야 F1도 높음 |
| **코퍼스 (corpus)** | 정확도를 측정하기 위해 미리 "여기엔 시크릿 있음/없음"이라고 답을 표시(레이블)해둔 테스트용 데이터 모음 |
| **레이블 (label)** | 코퍼스의 각 데이터에 붙인 정답 표시 |
| **베이스라인 (baseline)** | 비교 기준이 되는 이전 결과 또는 다른 도구(gitleaks 등)의 결과 |
| **과적합 (overfitting)** | 자기가 만든 테스트 데이터에만 잘 맞도록 도구를 튜닝해서, 실제 일반적인 상황에서는 그만큼 잘 안 맞을 수 있는 상태 |

## 8. 기술 스택 관련 용어

| 용어 | 뜻 |
|---|---|
| **Go (언어)** | 이 프로젝트가 쓰인 프로그래밍 언어. 컴파일하면 설치 과정 없이 실행 파일 하나로 배포 가능 |
| **단일 실행 바이너리 (single binary)** | 의존성 설치 없이 파일 하나만 있으면 바로 실행되는 형태의 프로그램 |
| **goroutine** | Go 언어에서 여러 작업을 동시에(병렬로) 처리할 수 있게 해주는 경량 스레드 |
| **cobra (spf13/cobra)** | Go로 `secrethound scan`처럼 서브커맨드가 있는 CLI 도구를 만들 때 쓰는 라이브러리 |
| **YAML** | 사람이 읽기 쉬운 설정 파일 형식. 이 프로젝트의 룰셋(`rules/default.yaml`)이 이 형식 |
| **os/exec** | Go 표준 라이브러리 중 외부 명령어(여기선 `git`)를 실행할 때 쓰는 기능 |
| **표준 라이브러리 (stdlib)** | 언어 자체에 기본으로 포함된 기능들. 외부 패키지를 추가로 설치하지 않아도 되는 것들 |

## 9. progress.md에 나오는 추가 용어

### 검증/안정성 관련

| 용어 | 뜻 |
|---|---|
| **회로 차단 (circuit breaker)** | "오프라인 회로 차단"이라고 나오는 개념. 연속으로 몇 번 실패하면 "지금은 네트워크가 안 된다"고 판단해서, 남은 요청들을 다 시도해보지 않고 바로 건너뛰는 안전장치. 인터넷 없는 CI에서 수백 번 타임아웃을 기다리는 걸 막아줌 |
| **redact (지우기/마스킹)** | 로그나 에러 메시지에 시크릿 값이 섞여 나올 수 있을 때, 기록하기 직전에 그 값을 지우는 것. "에러 문자열 redact"는 API 에러 응답에 키 값이 포함돼도 로그에는 안 남게 처리했다는 뜻 |
| **마스킹 (masking)** | 값을 화면에 보여줄 때 `ghp_9m******2pXk`처럼 일부만 보이고 나머지는 가리는 것. redact와 비슷하지만, redact는 "완전히 안 남김", 마스킹은 "일부만 보여줌"에 가까움 |
| **httptest (로컬 테스트 서버)** | 실제 AWS·GitHub 서버 대신, 테스트할 때만 임시로 띄우는 가짜 서버. "현재 테스트는 전부 로컬 httptest 서버 기준"이라는 말은, 진짜 API 응답이 문서와 조금이라도 다르면 테스트를 통과해도 실제로는 오작동할 수 있다는 위험을 뜻함 |
| **테스트 벡터 (test vector)** | 어떤 계산(여기선 AWS SigV4 서명)이 맞는지 확인하기 위해 미리 정답이 정해져 있는 입력/출력 예시. AWS가 공식적으로 공개한 값으로 자체 구현이 맞는지 검증함 |

### 개발 프로세스 관련

| 용어 | 뜻 |
|---|---|
| **Definition of Done (완료 기준, DoD)** | "이 정도가 되면 끝난 것으로 친다"를 미리 정해둔 체크리스트. 기획서의 "MVP 완료 기준" 항목이 이것 |
| **로드맵 (roadmap)** | 앞으로 할 일들을 우선순위·순서대로 나열한 계획표 |
| **회귀 테스트 (regression test)** | 예전에 고친 버그가 나중에 다시 생기지 않는지 확인하는 테스트. GitLab PAT 룰 버그를 고친 뒤 "eval 코퍼스에 회귀 케이스를 추가"한 것이 이 경우 |
| **정답 레이블 / ground truth** | 테스트 데이터에서 "이건 진짜 시크릿이다/아니다"라고 사람이 미리 정해둔 정답 |
| **커버리지 (coverage)** | 전체 룰 중 몇 개가 실제로 테스트(평가 코퍼스나 검증기)로 확인됐는지의 비율. "29/29"면 룰 전부가 확인됐다는 뜻 |
| **옵트인 (opt-in)** | 기본은 꺼져 있고, 사용자가 명시적으로 켜야만 동작하는 방식. `--validate`나 PII 룰(`--tags pii`)처럼 위험하거나 호불호가 갈리는 기능에 씀 (반대말: opt-out, 기본 켜짐) |
| **태그 (tag, rule tags)** | 룰마다 붙이는 분류표(`internal`, `pii` 등). `--tags`로 특정 태그의 룰만 골라 켤 수 있게 만드는 용도 |

### 그 외

| 용어 | 뜻 |
|---|---|
| **워커 풀 (worker pool)** | 여러 goroutine(작업자)을 미리 정해진 개수만큼 만들어두고, 일감을 나눠 동시에 처리하게 하는 병렬 처리 방식. `runtime.NumCPU()`는 "이 컴퓨터의 CPU 코어 수"를 알아내는 Go 함수로, 보통 워커 개수의 기본값으로 씀 |
| **push protection** | GitHub이 자체적으로 제공하는 기능으로, 코드를 push할 때 시크릿처럼 보이는 값이 있으면 미리 막아주는 것. 이 프로젝트의 평가용 가짜 키 14건이 여기에 걸려서 "테스트 데이터니까 허용해달라"고 예외 처리한 적이 있음 |
| **CRLF / LF (줄바꿈 문자)** | 텍스트 파일의 줄바꿈 방식. Windows는 CRLF, Linux/Mac은 LF를 씀. 이게 섞이면 `gofmt`(포맷 검사 도구) 같은 게 오작동할 수 있어 `.gitattributes`로 통일함 |
| **gofmt** | Go 코드의 형식(들여쓰기, 공백 등)을 자동으로 맞춰주고 검사하는 공식 도구 |
| **go vet** | Go 코드에서 흔한 실수(잘못된 형식 문자열 등)를 미리 잡아주는 정적 분석 도구 |
| **remediation (사후 대응)** | 시크릿을 찾아낸 "이후"에 무엇을 해야 하는지 안내하는 것. 예: "이 키는 이렇게 폐기하세요", `git filter-repo`로 히스토리에서 제거하는 명령 생성 |
| **`git filter-repo`** | git 히스토리 자체를 다시 써서 과거 커밋에서 특정 파일/값을 완전히 지워버리는 도구. (주의: 이미 폐기하지 않은 키를 히스토리에서만 지우면, 키 자체는 여전히 살아있어 위험함) |
| **Luhn 알고리즘** | 카드번호가 형식적으로 유효한지 검증하는 체크섬 계산법. 정규식만으로는 진짜 카드번호와 무작위 숫자열을 구분 못 하므로 이런 별도 계산이 필요함 |
| **체크섬 (checksum)** | 어떤 값이 규칙에 맞게 만들어졌는지 확인하기 위해 계산하는 검증용 숫자. 주민등록번호의 "가중치 검증"도 일종의 체크섬 계산 |
| **가중치 검증 (weighted checksum)** | 주민등록번호처럼, 각 자릿수에 정해진 숫자를 곱하고 더해서 마지막 자리(검증 숫자)와 맞는지 확인하는 방식 |
